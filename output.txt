──────────────────────────────────────────────────────────────────────────────
── 
  OVERVIEW: WHAT DOES THIS PIPELINE DO? 
──────────────────────────────────────────────────────────────────────────────
── 
 
This pipeline takes a heart disease dataset (CSV file) and trains a machine 
learning model to predict whether a patient has heart disease (1) or not (0). 
 
It does this in 7 steps: 
  1. Load and clean the data 
  2. Train a baseline Random Forest model 
  3. Select the most important features 
  4. Retrain RF on selected features 
  5. Tune hyperparameters using Random Search 
  6. Tune hyperparameters using Cuckoo Search 
  7. Build and evaluate the final best model 
 
At the end, optionally enters interactive mode where you type patient values 
and the model tells you if heart disease is detected.

── 
  EXECUTION FLOW (how the script runs from top to bottom) 
──────────────────────────────────────────────────────────────────────────────
── 
 
When you run: 
    python cli_pipeline.py

  3. If --predict flag was passed, calls interactive_predict()

WHAT IS RandomForestModel? 
  A custom wrapper class (defined in randomforest.py) around scikit-learn's 
  RandomForestClassifier. It simplifies training and evaluation. 
 
WHAT IS A RANDOM FOREST? 
  A Random Forest is an ensemble of many Decision Trees. Here's how it works: 
 
  1. DECISION TREE: A flowchart-like model. For each patient, it asks 
     questions like: "Is age > 55?" → if yes, go right; if no, go left. 
     It keeps splitting until it reaches a prediction. 
 
  2. RANDOM FOREST: Instead of one tree, it builds 150 trees (n_estimators=150). 
     Each tree is trained on a RANDOM SUBSET of the training data (sampling 
     with replacement — called "bootstrapping") and considers only a random 
     subset of features at each split. 
 
  3. PREDICTION: Each of the 150 trees votes. The majority vote wins. 
     e.g., if 110 trees say "disease" and 40 say "no disease" → prediction = disease. 
 
WHY RANDOM FOREST? 
  - More accurate than a single decision tree (reduces overfitting) 
  - Handles both numerical and categorical data 
  - Automatically handles feature importance 
  - Robust to outliers 
  - Works well on small-to-medium medical datasets 
 
PARAMETER: 
  n_estimators=150 → number of trees in the forest 
                     More trees = more stable predictions, but slower training. 
                     150 is a good default balance. 
 
────────────────────────────────────── 
  rf_baseline.train(X_train, y_train) 
────────────────────────────────────── 
 
WHAT IT DOES: 
  Internally calls RandomForestClassifier.fit(X_train, y_train). 
  "fit" = train the model. The model looks at all 720 training patients 
  and their labels (0 or 1) and learns patterns: 
    "Patients with high chest pain type (cp) and low max heart rate 
     (thalach) tend to have heart disease." 
 
RESULT: 
  The model's 150 trees now have their splitting rules set based on the 
  training data. The model is ready to make predictions. 
 
────────────────────────────────────── 
  metrics_b = rf_baseline.evaluate(X_test, y_test) 
────────────────────────────────────── 
 
WHAT IT DOES: 
  Makes predictions on the 180 test patients and compares to true labels. 
 
HOW METRICS ARE CALCULATED: 
 
  ACCURACY: 
    = (number of correct predictions) / (total predictions) × 100 
    e.g., 149 correct out of 180 = 82.78% 
    This is the most intuitive metric: "what % did we get right?" 
 
  CONFUSION MATRIX (foundation for other metrics): 
    Imagine a 2×2 grid of actual vs predicted: 
 
                      Predicted: No  |  Predicted: Yes 
    Actual: No           TN (True Neg)     FP (False Pos) 
    Actual: Yes          FN (False Neg)    TP (True Pos) 
 
    TN = correctly said "no disease" when there was none 
    TP = correctly said "disease" when there was disease 
    FP = falsely said "disease" when there was none (false alarm) 
    FN = falsely said "no disease" when there WAS disease (missed case) 
 
  PRECISION: 
    = TP / (TP + FP) 
    "Of all patients we predicted HAVE disease, what % actually do?" 
    High precision = fewer false alarms 
    e.g., 81.65% means when we say "disease", we're right 81.65% of the time 
 
  RECALL (Sensitivity): 
    = TP / (TP + FN) 
    "Of all patients who ACTUALLY have disease, what % did we catch?" 
    High recall = fewer missed cases 
    e.g., 89.00% means we caught 89% of actual heart disease patients 
    WHY IMPORTANT: In medicine, missing a disease (FN) is often worse 
    than a false alarm (FP). High recall is critical for diagnosis. 
 
  F1 SCORE: 
    = 2 × (Precision × Recall) / (Precision + Recall) 
    The harmonic mean of precision and recall. 
    Balances both metrics. Useful when you care about both. 
    e.g., F1 = 2 × (0.8165 × 0.89) / (0.8165 + 0.89) = 85.17% 
 
  AUC-ROC (Area Under the ROC Curve): 
    The model doesn't just output 0 or 1 — it outputs a probability 
    (e.g., 73% chance of disease). The threshold (usually 0.5) converts 
    this to 0 or 1. 
    ROC Curve: plots True Positive Rate vs False Positive Rate at every 
    possible threshold from 0 to 1. 
    AUC = area under that curve. Range: 0.5 (random) to 1.0 (perfect). 
    e.g., AUC = 0.884 means the model is very good at ranking sick 
    patients above healthy ones. 
 
RETURN VALUE: 
  metrics_b = { 
      'accuracy':  82.78, 
      'precision': 81.65, 
      'recall':    89.00, 
      'f1':        85.17, 
      'roc_auc':   0.884 
  } 
 
────────────────────────────────────── 
  fi = rf_baseline.feature_importances(list(X.columns)) 
────────────────────────────────────── 
 
WHAT IT DOES: 
  Calculates how important each feature (column) was to the model's 
  decisions. Returns a sorted list of dicts: [{'feature': 'cp', 
  'importance': 0.1678}, ...] 
 
HOW IMPORTANCE IS CALCULATED (Gini Importance / Mean Decrease Impurity): 
  At each split in each tree, a feature reduces "impurity" (how mixed 
  the classes are). A feature that consistently creates clean splits 
  (most patients on the left have disease, most on the right don't) 
  gets a higher importance score. 
  The final score = average reduction in impurity across all trees, 
  normalized so all importances sum to 1.0. 
 
EXAMPLE OUTPUT: 
  cp       0.1678  → chest pain type is most important 
  thalach  0.1415  → max heart rate is 2nd most important 
  chol     0.1280  → cholesterol is 3rd 
  ... 
 
WHY USED: 
  Tells us which patient attributes the model relies on most. 
  Used in Step 3 to decide which features to keep.

WHAT IS HYPERPARAMETER TUNING? 
  The Random Forest has settings (hyperparameters) that aren't learned 
  from data — they must be set before training. Examples: 
    - How many trees? (n_estimators) 
    - How deep can trees grow? (max_depth) 
    - Minimum samples to split a node? (min_samples_split) 
    - Minimum samples in a leaf? (min_samples_leaf) 
 
  Finding the best combination is called hyperparameter tuning. 
 
WHAT IS RANDOM SEARCH? 
  A custom class (in cuckoo_search.py or randomsearch.py) that tries 
  random combinations of hyperparameters and keeps the best one. 
 
PARAMETERS: 
  n_iterations=30 → try 30 random combinations 
  cv_folds=5      → use 5-fold cross-validation to evaluate each combo 
 
WHAT IS 5-FOLD CROSS-VALIDATION? 
  Instead of using a fixed train/test split, k-fold CV: 
  1. Divides training data into 5 equal parts (folds) 
  2. Trains on 4 folds, tests on the remaining 1 fold 
  3. Rotates which fold is the test fold, 5 times total 
  4. Averages the 5 accuracy scores 
  This gives a more reliable estimate than a single split. 
 
HOW random.optimize() WORKS: 
  For each of 30 iterations: 
    1. Randomly pick values for n_estimators, max_depth, 
       min_samples_split, min_samples_leaf 
    2. Train RF with those values using 5-fold CV 
    3. Record the average CV accuracy 
  Keep the combination with the highest CV accuracy. 
 
PARAMETERS to optimize(): 
  None         → no base model needed (RS creates its own) 
  X_train_fs   → training features (selected features only) 
  X_test_fs    → test features (for final evaluation) 
  y_train      → training labels 
  y_test       → test labels 
  progress_cb=rs_cb → callback function called after each iteration 
                       to update the progress bar 
 
CALLBACK FUNCTION rs_cb(info): 
  Called after each of the 30 iterations with an 'info' dict containing: 
    info["best_score"]  → best accuracy found so far 
    info["iteration"]   → current iteration number 
  rs_history.append(info["best_score"]) saves the history for analysis. 
  progress_bar(...) updates the terminal display. 
 
RETURN VALUES: 
  rs_params → list [n_estimators, max_depth, min_samples_split, 
                    min_samples_leaf] for the best combo found 
  rs_score  → accuracy of the best combo on the test set 
  _         → third return value (ignored, likely CV history)

WHAT IS CUCKOO SEARCH? 
  A nature-inspired optimization algorithm that mimics the behavior of 
  cuckoo birds, which lay eggs in other birds' nests. 
 
  METAPHOR: 
    - Each "nest" = one set of hyperparameters 
    - Each "egg" = the solution quality (CV accuracy) 
    - Cuckoos lay eggs in random nests (try new hyperparameter combos) 
    - Host birds discover foreign eggs and abandon them (discard bad solutions) 
 
  ALGORITHM: 
    1. Start with n_nests random hyperparameter combinations 
    2. For each iteration: 
       a. Generate new solutions using Lévy flight (random walks with 
          occasional big jumps — models cuckoo's random wandering) 
       b. Evaluate each nest (train RF, get CV accuracy) 
       c. If a new nest is better than an existing one, replace it 
       d. With probability pa (abandon rate), randomly abandon worst nests 
          and generate new random ones 
    3. Return the best nest found 
 
PARAMETERS: 
  n_nests=30       → number of nests (parallel solutions being tracked) 
                     NOTE: Your code says "40 nests" in the header but 
                     creates CuckooSearch(n_nests=30) — inconsistency. 
  n_iterations=10  → number of rounds of optimization 
                     NOTE: Header says "30 iterations" but code has 10 — bug. 
  pa=0.15          → probability of abandoning a nest (15%) 
                     Low pa = more exploitation of good solutions 
                     High pa = more exploration of new solutions 
  cv_folds=5       → 5-fold cross-validation for each evaluation 
 
LÉVY FLIGHT (how new solutions are generated): 
  Instead of small random steps, Lévy flight occasionally makes very 
  large jumps. This helps escape local optima (situations where small 
  changes don't improve things but a big change would). 
  Mathematically: step size follows a power-law distribution. 
 
WHY CUCKOO SEARCH OVER SIMPLE RANDOM SEARCH? 
  Random search is purely random — it doesn't learn from previous results. 
  Cuckoo Search is "smarter" — it concentrates search around good solutions 
  while still exploring. In theory, it should find better solutions with 
  fewer evaluations. In practice (as your results show), both got 83.33%, 
  suggesting the search space may be too narrow or 30 iterations was 
  enough for random search to find the optimum too. 
 
PARAMETER rf_dummy: 
  cs.optimize() expects a RandomForestModel object as its first argument 
  (possibly to inherit some configuration). Since CuckooSearch builds its 
  own RF internally, rf_dummy = RandomForestModel() is just a placeholder. 
 
RESULT FROM YOUR RUN: 
  Best score: 83.33% 
  n_estimators: 167, max_depth: 19, min_samples_split: 4, min_samples_leaf: 5 
  Same accuracy as Random Search — both found similar solutions.

PARAMETER CLAMPING: 
  n_est     = max(10,  min(300, int(round(best_params[0])))) 
  max_d     = max(3,   min(20,  int(round(best_params[1])))) 
  min_split = max(2,   min(20,  int(round(best_params[2])))) 
  min_leaf  = max(1,   min(10,  int(round(best_params[3])))) 
 
  WHY CLAMPING? 
  The optimization algorithms work in continuous space (they might output 
  167.43 for n_estimators). We need integers, and we also want to enforce 
  sensible bounds to prevent extreme values: 
    - n_estimators: minimum 10 (at least some trees), max 300 
    - max_depth: minimum 3 (at least some depth), max 20 (prevent 
      overfitting — very deep trees memorize training data) 
    - min_samples_split: minimum 2 (scikit-learn default), max 20 
    - min_samples_leaf: minimum 1, max 10 
 
  int(round(...)) converts the float to the nearest integer. 
  max(lower, min(upper, value)) clamps to [lower, upper] range.

  ) 
 
  n_jobs=-1 → use ALL available CPU cores for parallel training 
              Each tree can be built independently, so this speeds up

SIGNATURE: 
  def interactive_predict(state: dict) 
 
PARAMETER: 
  state → the dictionary returned by run_pipeline(), containing: 
          state["rf"]                → the trained final model 
          state["selected_features"] → list of feature names to prompt for 
 
HOW IT WORKS: 
  1. Retrieves the trained model and feature names from state. 
  2. Enters a while True loop (runs forever until user types 'q' or 'n'). 
  3. For each feature in selected_features: 
     - Prompts the user to enter a numeric value 
     - Validates input (must be a number, not text) 
     - Stores in row_vals list 
  4. Creates a pandas DataFrame with one row from the entered values. 
  5. Calls rf.predict_proba_single(row): 
     - This runs the trained RF on the entered values 
     - Returns the probability that the patient has heart disease (0 to 1) 
  6. If probability >= 0.5 → predict class 1 (heart disease) 
     If probability < 0.5  → predict class 0 (no heart disease) 
  7. Displays result and probability. 
  8. Asks if user wants to run another prediction.

ERROR HANDLING:
